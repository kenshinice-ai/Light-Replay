# Light Replay：回家后在照片上拖时间看光——方案与执行清单

对应：`00-blueprint.md` §3 首发范围、`02-architecture.md` §2–3、`03-scene-record.md` §5 / §7、`04-capture-protocol.md` §11、`06-sun-model.md` §4–8、ADR-0010（Vision 分割首选）、ADR-0013（"测得"的数字只来自工具）、ADR-0019（存网格 + 关键帧掩膜，Save 之后算）、ADR-0020（姿态 10 Hz）。
配套的概念图页面：同日发布的 artifact「Light Replay 方案」（图 1–4 的源文件在本文件末尾的说明里）。

## 1. 要做出来的体验（一句话）

看房时在客厅沙发的位置扫 30 秒；回家后点开那张照片，把时间滑到 7 月 8 点、12 月 4 点，照片上显示那一刻太阳在哪、照不照得到这个位置，下面一条色带写明一天里哪几段有直射。

三条不变的原则（`14-design-principles.md`）在这一屏上的落点：

- **数字来自工具**：每个时刻、每段时长由 SunEngine 从可见域网格算出；文案（Assist）只能复述，不能产生。
- **未知就说未知**：没有分割的记录（R0）不出小时数；北向只有罗盘时，边界是一段阴影而不是一条线，并写"大约，±N 分钟"。
- **等级与来源可见**：R1 / 覆盖率 / 北向来源 / 玻璃占比 / 算法版本，在同一屏下方，不藏在设置里。

## 3. 回放屏的设计

### 3.1 入口

- 房产页 › Light 区块 › 这次扫描的卡片（缩略图是 Hero 照片）。
- Compare › Natural light 格：显示冬至直射时长（R1 且走廊灯通过时）或"大约 N 小时"（北向只有罗盘）或"尚未计算"（R0），点开进回放屏。
- 房产页的照片流里，Light 扫描的 Hero 与普通照片并列，右上角有太阳角标，点开即回放。

### 3.2 布局（图 1）

从上到下，一屏放下，不滚动也完整；细节区可下拉：

1. **照片**：Hero 照片，保持拍摄时的比例。叠加：当天的太阳弧（10 分钟一点）、所选时刻的太阳标记、标记的状态色（直射 = 太阳黄实心；被挡 = 灰色空心，并把遮挡它的那片画面轻微描边；敏感 = 黄色描边 + 斜纹）。太阳不在照片视野里时，在照片边缘画一个指向它的小箭头和"在右侧 40°"。
2. **日期行**：四个胶囊——冬至 21 Jun（默认）、春分、夏至 21 Dec、今天；长按任一胶囊出日期选择器。
3. **时间滑杆**：从日出到日落，每小时一刻度，手指 1:1 跟手；滑杆下面就是**当天的色带**：直射 / 敏感（斜纹）/ 被挡 / 未知（空心）。手指过色带边界时一次轻触感（apple-design：按下即反馈，不过冲，可中断，reduced motion 下只去掉滑动动画不去掉触感）。
4. **一句结论**：`21 Jun · 直射 10:40–14:10 · 3 h 30 min`；北向只有罗盘时在后面加 `· 大约，边界 ±50 min`；R0 时这一行写"日照尚未计算"，色带整条空心。
5. **证据行**（可展开）：等级 R1 · 走廊覆盖 94% · 北向 罗盘 ±13°（黄）· 玻璃 0% · 算法 sun-1.0 / vis-0.1 / north-0.2 · 计算于 10-03 18:21。

### 3.3 第二个视图：天幕（图 2）

照片的视野通常只有 60–70°，装不下一整条太阳弧。向下滑或点"天幕"切到 360 × 100 的可见域网格展开成的全景条：横轴方位（以照片朝向居中），纵轴高度角；天空 / 遮挡 / 未知 / 玻璃四态着色，三条太阳弧（冬至、春分、夏至）叠在上面，所选时刻的太阳标记同步。这一视图不需要 Hero 照片也成立，是"为什么这段被挡"的解释来源（`analysis[].attribution`：`blocked_west` 等）。

### 3.4 不做的

不显示亮度、温度、天气；不给评分；不比较两套房的"谁更好"（Compare 只并列数字）；不在 R0 上画任何色带。

## 4. 数据与计算（图 3）

### 4.1 扫描期间多留两样东西

| 新增 | 内容 | 大小【估】 |
|---|---|---|
| Hero 照片 | 锚定帧的静帧（`capturedImage` → HEIC，长边 2048），连同该帧的 `camera_transform` 与 `intrinsics`（已在 `hero_frame`） | 0.8–1.5 MB |
| 帧卷（frame spool） | 扫描中按 **3–5 fps**【估】抽帧（只取追踪正常、漂移 ≤ 容差、转速 ≤ 60°/s 的帧，`SkySweep` 的计入规则），降采样到长边 960 的 JPEG，暂存在 Caches，不进记录 | 30 s ≈ 120 帧 ≈ 15 MB 临时 |

帧卷是 ADR-0019"Save 之后算"的前提：分割要有图可算。计算完成后只保留 3–5 张关键帧的掩膜（锚定帧 + 覆盖增量最大的几帧），帧卷删除。

### 4.2 Save 之后的流水线（`LightAnalysisJob`）

```
Save（R0 记录已写入，行已存在）
  → 1 分割：每帧 Vision GenerateIterativeSegmentationRequest，几何种子（高度角 > 30° 且在走廊内 = 天空正种子；LiDAR 深度 < 4 m = 遮挡负种子）→ 掩膜 + 置信度
  → 2 四态：高置信天空 / 高置信非天空 / 低置信 = 未知 / 反射启发式命中 = 玻璃不确定
  → 3 落格：对视锥内每个网格格，把格中心投到像素（PinholeCamera.pixel(of:)），读标签与置信度；边缘 8% 不读；有近深度则重投影到目标点
  → 4 累积：VisibilityAccumulator 逐格计票（置信度加权），最终态取多数且 ≥ 3 票【估】，相持 = 未知，玻璃可疑压过天空
  → 5 覆盖与灯：SunCorridor.coverage → QualityEvaluator 重算走廊 / 方向 / 分割三盏灯
  → 6 时段：SunBands 对四个标准查询（冬至 ±6 周、春分、夏至、全年热力图）
  → 7 写回同一条记录（scene_id 不变）：visibility.*、analysis[]、quality、app.algorithms 版本；level 由灯决定（任一阻断仍是 R0）
  → 8 行上的状态文字从"日照尚未计算"换成结论句；Compare 格更新
```

- 触发：Save 完成后立刻在前台 `Task` 跑；App 退到后台由 `BGProcessingTask` 续跑；按 `scene_id` 幂等，重跑覆盖。
- 失败：记录仍是 R0，行上写"分析未完成，可重试"，不丢扫描。
- 时长目标：30 秒扫描在 iPhone 17 Pro 上 **≤ 20 秒**【估，W1 测】，进度显示在行上。

### 4.3 投影到照片

Hero 的 `intrinsics` 与 `camera_transform` 给出 `PinholeCamera`；每个太阳样本 `(az_true, alt)` → `az_ar = az_true − Δ` → 方向向量 → `pixel(of:)`。Δ 有 σ 时，标记旁画一段 ±σ 的弧（而不是一个点）。照片按 `capturedImage` 原生横向坐标存储，显示时按 Hero 帧的界面方向旋转（横持扫描已验 10-03）。

### 4.4 不确定度怎么进色带

`SunBands` 已按 `YawEstimate(σ)` 抽 64 组 Δ：某时刻在所有抽样下都直射 = 直射；都被挡 = 被挡；有的直射有的被挡 = **敏感**。色带的敏感段宽度就是"±N 分钟"的来源，文案直接取 `segments` 的分钟数，不另算。

## 5. 诚实边界与等级

| 记录状态 | 色带 | 结论句 | 怎么到下一级 |
|---|---|---|---|
| R0（无分割或任一阻断） | 整条空心 | 日照尚未计算 / 分析未完成 | 跑完流水线且三盏灯不阻断 |
| R1 · 北向黄灯（罗盘一组，σ ≤ 6° 不可能，所以是"一组且 σ > 6° → 阻断"？否——见下） | | | |

注意 `04` §6 的方向灯：只有罗盘一组且 σ > 6° 是**阻断**，不是警告。10-03 的真机 σ 是 10–20°。这意味着**只靠罗盘，记录永远到不了 R1，回放屏永远是空心色带**。两条路：

- **A. 最小确认（推荐先做）**：Save 时如果方向灯阻断，让买家做一次 15 秒的确认——晴天点一下太阳或地上的光斑（`sun_disk` / `window_patch`，solar 组 σ 2°）；阴天把墙面对到地图足迹（`wall_footprint`，map 组 σ 4°）。任一成功即与罗盘佐证或单独成组（σ ≤ 6° → 警告 → 可出 R1）。这是 `04` §7 本来的设计，W2 的内容提前到现在。
- **B. 放宽规则**：允许"一组且 σ ≤ 20°"出带宽敏感段的 R1。不推荐：ADR-0018 刚把佐证收紧，σ 15° 意味着时间轴上 ±1 小时，色带会有一半是斜纹，产品看起来像在猜。

本方案按 A：回放屏第一版就要求有一次方向确认，没有确认的扫描停在 R0，照片与天幕仍可看，色带空心，并给出"去确认方向"的按钮（回到现场才能做，所以也要在扫描结束时就提示）。

## 8. 风险与退路

| 风险 | 征兆 | 退路 |
|---|---|---|
| Vision 分割不达线 | W1 IoU < 0.90 或檐下 / 树冠失败不可识别 | ADR-0010：CoreAI 自训模型，多 1–2 周；期间回放屏只给"天幕 + 未知"视图 |
| 玻璃反射假天空 | 隔玻璃帧把室内灯判成天空 | 启发式压成"玻璃不确定"；分割灯警告；FM 关键帧判断（W2）后接 |
| 没人做方向确认 | 扫描都停在 R0 | 把确认做成 Save 前的最后一步而不是可选项；光斑点选 5 秒 |
| 计算太慢 / 费电 | 30 秒扫描分析 > 60 秒 | 帧卷降到 2 fps、长边 640；BGProcessing |
| 记录体积 | 分析后记录 > 3 MB | 掩膜只留 3 张；`states.png` 是 36 KB 的调色板 PNG |

## 9. 六问（`14` §8）预答

1. 这一屏服务"回家决定要不要再去看一次 / 要不要出价"；多出来的只有证据行，可折叠。
2. 每个结论带等级（R0 / R1）、来源（罗盘 / 太阳 / 墙面）、σ；未知是空心段，不是空白。
3. 没有任何数字来自模型：时刻与分钟数来自 `SunBands`，文案模板只填数。
4. 滑杆 1:1 跟手、无过冲、可中断；reduced motion 下仍可用。
5. 文案给区间（±N 分钟），不说"精确 / 认证"。
6. 不新增权限（相机与定位已在扫描时授予；BGProcessing 不需要用户授权）。
