# 天空分割：把"镜头看过"变成"那里是天空"的方案

日期：2026-10-03。作者：Claude。状态：提案，等 Lee 定方向后动手。
对应：`02-architecture.md` 第 1、3、6 节（VisibilityCore），`04-capture-protocol.md` 第 5、6 节，ADR-0010（Vision 交互式分割为首选），`07-spike-plan.md` W1 的分割路径评估。

## 1. 现在卡在哪

Light scan 已经记下每一帧镜头朝向哪里（`SkySweep`），SunEngine 已能按一张 360 × 100 的可见域网格算出全年时段（`SunBands`），QualityEvaluator 已能按网格里的证据判走廊与分割两盏灯。缺的是中间那一步：**把相机帧变成网格里的 天空 / 遮挡 / 未知 / 玻璃不确定 四态**。这一步接上之前，记录永远是 R0，结果卡永远写"日照尚未计算"。

## 2. 管线（按 02 第 3 节的坐标约定，不另起炉灶）

| 步 | 做什么 | 已有 / 待做 |
|---|---|---|
| 选帧 | 扫描中每秒取 3–5 帧【估】：追踪正常、漂移 ≤ 容差、转速 ≤ 60°/s（这三条 `SkySweep` 的计入规则已经在用） | 已有规则，待接出帧 |
| 分割 | Vision `GenerateIterativeSegmentationRequest`。种子由几何生成：按重力算出的高度角 > 30° 且在太阳走廊带内的像素作"天空"正种子【估】；LiDAR 深度 < 4 m 的像素作"遮挡"负种子。输出掩膜 + 置信度 | 待做；首次使用前下载模型资源，未下载时手工涂抹并标 `manual`（ADR-0010 降级） |
| 四态 | 高置信天空 → 天空；高置信非天空 → 遮挡；低置信 → 未知；反射可疑 → 玻璃不确定（第一版只用启发式：画面里出现室内灯具 / 家具的镜像、亮度异常一致的"天空"、深度指示在玻璃面附近；FM 关键帧判断后接） | 待做 |
| 像素 → 方向 | 反着做比正着做省：对每个在视锥内的网格格（`SkySweep` 已算出），把格中心方向投影到像素（`PinholeCamera.pixel(of:)` 已有），读掩膜标签与置信度；每边 8% 的边缘不读 | 投影已有，采样待做 |
| 深度重投影 | 该像素有 LiDAR 深度且 z < 4 m：算出遮挡点，从目标点重新定向后落格（02 第 3 节公式） | 待做 |
| 累积 | 每格按状态计票（置信度加权）；最终态取多数且票数 ≥ 下限【估 3 票】；多数不够或两态相持 → 未知；玻璃可疑压过天空 | 待做：这是 **VisibilityCore** 的核心，纯算法 |
| 输出 | `visibility.states_ref` / `confidence_ref`（360 × 100 PNG）、`votes`、`coverage`（`SunCorridor.coverage` 已有）、用过的帧标 `used_for_visibility: true` 并给 `mask_ref` | 格式在 03 第 5 节已定 |
| 质量 | 分割灯按玻璃占比（QualityEvaluator 已有）；"反射未识别"要给 schema 加证据字段（反射启发式的触发计数、FM 标记）→ schema 0.2 | 待做 |

## 3. 哪些现在就能做、哪些要真机

- **现在能做（模拟器 + Python 对照）**：VisibilityCore 的累积与重投影——合成掩膜 + 已知姿态 → 网格，02 第 6 节的"物理对照夹具"（朝西的窗得到下午直射；水平画面上沿像素的高度角等于半个垂直视场角）。这一层写完，Vision 适配器只是一个薄壳。
- **要真机**：Vision 的实际分割质量、每帧延迟、模型资源下载、曝光（ARKit 不开放曝光锁定，只能记录 `exposureOffset`，这一条 04 第 5 节的"锁定较低曝光"可能做不到【验】）。
- **要 Lee**：W1 的评估集——自家 20 帧（开敞庭院、檐下、树冠；隔玻璃几帧），人工标天际线。通过线 IoU ≥ 0.90 且失败可识别（07 第 5 节）；不达线转 CoreAI 自训模型（ADR-0010 已定）。

## 4. 要 Lee 定的三件事

1. **掩膜存哪里。** 每帧掩膜 PNG 全存进记录（iCloud 空间 ×N）还是只存累积后的网格 + 几张关键帧掩膜。推荐后者：网格是证据，掩膜是过程；留 3–5 张关键帧够复算与排错【估】。
2. **什么时候算。** 扫描中实时（能提示"这片天空看到了"，耗电、复杂）还是按 Save 之后批量算（简单、省电、结果卡慢几秒出）。推荐 V1 先按 Save 后算，实时留给 spike 结论之后。
3. **评估集谁拍、何时拍。** 推荐 Lee 周末在家拍 W1 的三个点 + 两处隔玻璃，我出标注工具与指标脚本（`engine/metrics.py`，02 的计划里有）。

## 5. 顺序

VisibilityCore 累积（纯算法，先做）→ Vision 适配器 + 20 帧评估（要真机与 Lee）→ 分割灯补证据字段（schema 0.2）→ 结果卡换成时段（只在记录过 R1 之后）。每步一个 PR，数字全部标【验】【估】，通过线不事后放宽。
