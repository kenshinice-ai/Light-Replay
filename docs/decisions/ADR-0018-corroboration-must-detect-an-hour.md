# ADR-0018 · 一致不等于佐证：两组一致只在能抓住一小时误差时才点绿灯

- 状态：Accepted（2026-10-03，Lee 授权 Claude 决定）
- 日期：2026-10-03
- 细化：ADR-0009 的绿灯条件；`05-north-resolver.md` 第 3、6 节；`04-capture-protocol.md` 第 6 节方向灯

## 背景
ADR-0009 规定两个独立组一致即绿灯，并记下一个已知盲区：罗盘 σ = 12° 时，它与 solar 的冲突门槛是 `3·sqrt(2² + 12²) = 36.5°`，一个 17° 的 solar 错误藏得进去。2026-10-01 实现 NorthResolver 时又确认了它的极端形态：一组读数互相矛盾（σ 取到 90°）时，它与任何组都"一致"，仍被算作第二个独立来源而点亮绿灯。两种情形都是同一件事：**一致只有在它本可以不一致时才是证据**。门槛越宽，一致说明的越少；宽到一定程度，一致什么都不说明。

数量级（【估】，中纬度）：太阳方位角平均每小时转约 15°；进出遮挡时刻的误差约等于方位误差除以这个速率。一对"一致"若连 15° 的方位错误都抓不住，就等于没有第二个来源。

## 决定
1. **佐证**的定义：参与融合的组合里，一对组 i、j 的冲突门槛 `3·sqrt(σ_i² + σ_j²) ≤ 15°`（候选）。这对的一致本可以暴露一小时量级的方向错误，所以算作互相佐证。
2. 方向灯：
   - 绿灯：没有冲突（ADR-0009 第 3、4 条），且组合里至少有一对佐证。
   - 没有佐证对的组合（含只有一组）：按一组处理——融合 σ ≤ 6° 黄灯；否则红灯并要求一次最小确认，确认前只出 R0。
   - 冲突的处理不变。
3. 没有佐证的组照常参与融合（加权圆周均值）和冲突检测：它们能否决粗大错误、能收窄 σ，只是不能把灯点绿。
4. 15° 与 6° 一样是候选值，由日晷 spike 校准（`07` 第 5 节增加一行）；修订走 ADR。

## 后果
- 手机罗盘按 `05` 第 2 节的 8° 先验，`3·sqrt(8² + σ²) ≥ 24°`，**永远不能佐证**。V1 只有罗盘一个来源时，绿灯不可达：这是对现状的诚实描述，不是缺陷。绿灯要等墙面对齐、窗光斑或 VPS 任一接入。
- 两种已知盲区都由规则关闭，`05` 第 7 节改为问"15° 是否合适"。
- `northresolver-0.1 → 0.2`（输出的灯对同一输入会变，版本必须变）；`engine/tests/fixtures/north-cases.json` 重新生成；QualityEvaluator 不变（它只读方向灯），其用例随之更新。
- `03` 第 4 节示例里的 `algorithms.north` 版本号；`04` 第 6 节方向灯一行；`13` 加"佐证"。

## 备选
- **给佐证组加 σ 上限**（原设想，如 σ ≤ 6°）：只看一边。solar σ 2° 配 map σ 6°，门槛 19°，仍抓不住 15°；而 solar 1° 配 map 4.5° 门槛 13.8° 可以。该看的是这一对合起来能分辨多大的错，不是单个组的 σ。放弃。
- **保持 ADR-0009 原样，交给 spike 统计发生率**：spike 统计的是罗盘错多少，不是"一致"本身是否有意义；后者是逻辑问题，不需要数据来决定。放弃。
- **把罗盘排除出佐证**：结果上与本决定在 V1 相同，但规则写死了来源名，对将来 σ 更好的磁力计或更差的墙面对齐都不对。放弃。
