# ADR-0022 · SceneRecord 0.2：证据随记录走，五盏灯都能重算，结果有版本

- 状态：Accepted（2026-10-04，Lee 认可方案 v2 并要求结合 Codex 的 v2 复审开工）
- 日期：2026-10-04
- 影响：`00-blueprint.md` 第 22 行；`03-scene-record.md` §11；`04-capture-protocol.md` §6、§12；`ios/Packages/SceneRecord`；`engine/lightreplay/scenerecord.py`、`quality.py`
- 依据：评审 R01、R05、R06；复审 V2-03、V2-04、V2-05

## 背景
0.1.0 的记录用文件路径指向网格与掩膜，只有三盏灯有可重算的证据，没有"这是哪一次分析的结果"。回放要在另一台设备上打开同一条记录并相信它，这三件都不够。

## 决定
1. **两个版本并存。** 0.1.0 的记录照旧可读、可校验，按 quality-0.1 判；0.2.0 是新写入的格式，按 quality-0.2 判。两端校验器同步，共用 `engine/tests/fixtures/scene-v2-cases.json`。
2. **资产内联，带长度与哈希。** 可见域网格与置信度（各一字节一格，行优先，自最低高度角、方位 0 起）用原始 DEFLATE + base64 放进记录；关键帧掩膜（至多 5 张）用 PNG + base64。每个载荷声明宽、高、字节数与 SHA-256，校验器解码后逐项核对，解压有上限。`votes.cells` 必须是网格自己的直方图。Hero 照片的像素放在这一行已有的照片列，记录里写原始尺寸、编码尺寸、缩放、裁剪、旋转，且这条变换链必须自洽。
3. **五盏灯都按证据重算（quality-0.2）。** 追踪直接从扫描帧读；地平线、镜头、反射的检查结果写在 `quality.evidence`。**没跑的检查是缺证据，缺证据阻断；跑了没发现不等于不存在**，规则里不这样定义。规则表在 `04` §6。两处有意的取舍：
   - 画面里没有地平线（室内多数如此）不扣分：地平线只是对 ARKit 重力的旁证，不能因为它不在场就让所有室内扫描停在 R0。没检查则阻断。
   - 运动模糊不设单独的灯：由帧卷的入选规则（追踪正常、漂移在容差内、转速 ≤ 60°/s）挡在累积之前。
4. **结果有版本。** `result.revision`（0 = 刚保存、未分析）、`capture_digest`（采集输入清单的摘要，保存时定）、`north_digest`（方向候选的摘要，确认方向后变）、`inputs_hash`（分析输入的摘要，首次分析后才有）。分析任务开始时记下 `(行 uuid, capture_digest, north_digest, revision)` 作为提交令牌；提交在一个串行入口里完成：行还在、没被删、四项都没变，才写入并 revision + 1；数据库保存成功之后才清帧卷。首次分析之前没有网格，令牌不依赖它。
5. **只有采集设备生成结果，其他设备只读。** 两台设备各自比较 revision 不构成全局互斥，所以不设计成能并发写。
6. **系统状态不写进买家的文字。** 现在 Light 行的状态句写在 `text` 里，而 `text` 是买家可编辑的列。B 阶段起：行上加一个小摘要列（等级、五盏灯、覆盖、结果 revision、代表日的三种分钟数），列表与 Compare 读它；`text` / `originalText` 只属于买家。旧行的迁移：只有整句与旧模板完全相同、且从未被编辑过（`originalText` 为空）的才清空，其余原样保留。这需要一个新增的 CloudKit 字段（追加式部署）；"不新增字段"是偏好，不凌驾于数据分离之上。
7. **任务身份用行 uuid。** `scene_id` 是给人看的编号，跨设备同日会撞。恢复、查询、导出与关联路径在 B 阶段一并改用可靠身份。

## 后果
- 记录 JSON 变大：一次扫描的网格与掩膜内联后的实际体积、另一台设备上的读取内存，用真实样本量，不以估算为准。
- 0.1.0 的 R1 规则不变；0.2.0 的 R1 另需内联网格与至少一张关键帧掩膜。
- 当前 App 写出的仍是 0.1.0；B 阶段切到 0.2.0。

## 备选
- 继续用文件路径 + 每个资产一个 CloudKit 字段：本机路径在另一台设备上没有意义，字段随资产种类增长。放弃。
- 检查没跑时给警告而不是阻断：等于默认通过。放弃。
