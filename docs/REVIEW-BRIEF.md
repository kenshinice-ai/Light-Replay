# 给评审的说明

这是一个只有文档的分支：光境 / Light Replay 的蓝图、规范、ADR 与现场模板，没有代码。请把它当作一份技术产品方案来审，目标是找矛盾、漏洞和不可实现的承诺。

## 请重点审

1. **一致性。** 术语（`13-glossary.md`）、阈值（04 / 05 / 06 / 07）、证据等级 R0–R3 在各文档之间是否矛盾；蓝图第 2 节与各 ADR 是否一致。
2. **几何与约定。** `02-architecture.md` 第 3 节的像素到方向、AR 世界方位存储与真北旋转 Δ 的符号；`06-sun-engine.md` 的太阳几何、采样、时段分级是否有漏洞（南半球、夏令时、闰年、太阳圆面、折射）。
3. **NorthResolver（05）。** 独立组划分是否合理；融合与冲突判定会不会把错误藏进平均；σ 传播到时段的方法能否实现、成本多大。
4. **采集协议（04）与 SceneRecord（03）。** 字段是否足以复现结果并做 false-valid 检查；漂移的深度重投影（ADR-0006）在非 LiDAR 与远场的处理是否自洽；玻璃"四态"是否可从分割模型得到。
5. **Spike（07 / 08）。** 指标能否被实际测出；通过线能否证伪；holdout 与 false-valid 规则有没有漏洞；三周的工作量是否现实。
6. **合规与措辞（11 / 09 / 01）。** 有没有会被读成"认证"、"精确"或"预测天气"的句子；隐私默认是否足够；Light Passport 的来源标签能否防止选择性披露。

## 不必审

价格与市场规模（刻意未写）；风水与法律文件（刻意排除，见 ADR-0005）；策略稿存档（不在仓库）。

## 输出偏好

指出具体文件与行；矛盾优先于风格；每条给改法。数字上的【验】【引】【估】标注是刻意的，不必要求删除；"候选"阈值本来就是待测。
