# 08 · 现场真值协议（Paradise Production）

版本 0.1 · 2026-09-10

## 1. 目的

给每个目标点一份独立于 App 的观测：阳光**实际**何时到达、何时离开这个点；以及独立于手机传感器的真北。没有真值的采集只能算演示。

## 2. 前提

- 授权：`field/templates/consent-checklist.md` 全部勾选。
- 天气：至少两小时有明显直射；阴天只做采集时长与失败率，不做时刻误差。
- 人：一名采集员，一名记录员（可同一人）。

## 3. 设备

| 设备 | 用途 |
|---|---|
| iPhone（LiDAR） | OneTake 采集 |
| 第二台手机 + 小三脚架 | 延时：每 30 秒一张，固定曝光，对准目标点 |
| 白卡（A5，哑光） | 放在目标点，卡上有无直射一眼可辨 |
| 竖直杆（30 cm）+ 水平泡 | 日晷：影子给出真太阳方位 |
| 表 | 与手机时间同步（NTP） |

## 4. 步骤

1. 选目标点，放白卡；记录目标标签与高度。
2. 日晷：杆立在目标点旁，用 App 的 AR 模式点杆底与影尖各一次，App 记录 AR 向量与时刻；由已知太阳方位解出真北（`05-north-resolver.md` 第 2 节的 truth 组）。
3. OneTake 采集（按 `04-capture-protocol.md`）。记录采集秒数、漂移、四灯状态。
4. 延时开机，对准白卡与窗，覆盖预测的进出时刻前后各 30 分钟以上。
5. 离场前不看 App 的预测，避免记录员被引导。
6. 回看延时：记录白卡从无到有直射、从有到无的时刻（分钟级）。
7. 填两张表；把 scene_id 与延时文件对应。

## 5. holdout

- 到场前就决定该场景是否 holdout（W3 全部为 holdout）。
- holdout 的 SceneRecord 在分析前由 Lee 保管；算法参数冻结后才跑。

## 6. 记录字段

`capture-log.csv` 与 `timelapse-log.csv` 的列在 `field/templates/`。误差 = 预测 − 观测，分钟，带符号。

## 7. 隐私

- 延时画面只含白卡、窗、天空；有人入镜的片段删除。
- 文件只在采集设备与本机；不上传云端；不入库。
