# 07 · 三周技术 Spike：只回答"这条测量链有没有资格进入 MVP"

版本 0.1 · 2026-09-10 · 状态：未开始

## 1. 原则

- 不做产品 UI、不做付费、不做地图、不做预览。
- 通过线在开始前预注册（本文第 5 节）；事后修订走 ADR。
- 第 3 周的 holdout 场景不参与任何调参。
- **false-valid**（质量不够却输出确定小时数）是一票否决。

## 2. 三周

| 周 | 目标 | 交付 | 场景 |
|---|---|---|---|
| **W1 · Point Core** | OneTake 采集验证器 + SunEngine + 分割路径评估 | SceneRecord 导出；帧、姿态、深度、掩膜记录；镜头锚点与漂移；走廊覆盖率显示；SunEngine 单元测试通过；**Vision 交互式分割 + 几何种子在 20 帧标注上的 IoU、延迟、失败可识别率**；镜头脏污与地平线检查接入质量灯 | 自家：开敞庭院、檐下、树冠各 1 点 |
| **W2 · Hard Cases** | 室内、玻璃、NorthResolver | 四态分割（含玻璃不确定）；深度重投影；四来源方向并行记录与融合（ADR-0009 规则）；**FM 关键帧反射判断对 30 张标注帧的准确率与延迟**；R2 对照仅在 RoomPlan 可用时 | 自家与已授权室内：隔玻璃 3 点、开窗 2 点 |
| **W3 · Holdout** | PP 独立真值 | 10–15 个目标点（室内外各半，含玻璃、树冠、低太阳）；固定机位延时；日晷方向真值；误差分布、失败率、时长、人工救场分钟；若有余量，FM 教练句上线并记录救场分钟是否下降 | 授权房源，按 `08-ground-truth-protocol.md` |

## 3. 指标定义

| 指标 | 定义 |
|---|---|
| 时刻误差 | 每个"阳光进入 / 离开目标"事件：`|预测 − 观测|` 分钟；只统计通过质量门槛（accepted）的场景 |
| false-valid | 未通过门槛却输出小时数的场景数；或 accepted 场景中误差 > 45 分钟且无"敏感/未知"标注的事件数 |
| 采集时长 | 从按下开始到质量门槛判定的秒数；分布与放弃率 |
| 人工救场 | 每个成功场景需要采集员之外的人介入的分钟数 |
| 玻璃可用性 | 隔玻璃场景中：失败被系统识别的比例；未识别的假天空数 |
| 方向源分布 | 每种来源相对日晷真值的误差；冲突检测按"仅磁罗盘被否决"与"否决了其他组"两类分别报告触发率与正确率 |
| 漂移 | 每场景最大漂移；重投影前后走廊内单元变化率 |

## 5. 候选通过线（预注册，2026-09-10）

| 指标 | 候选线 | 备注 |
|---|---|---|
| 时刻误差 | accepted 场景中位数 ≤ 10 分钟，P90 ≤ 20 分钟 | 【估】先测分布 |
| false-valid | holdout 中为 0 | 一票否决 |
| 采集时长 | ≥ 80% 的点在 40 秒内 | 同时报 P80 / P90 与放弃率 |
| 人工救场 | 中位数 0 分钟；任何场景不超过 5 分钟 | 频繁需专家校北即不成立 |
| 玻璃可用性 | 未识别的假天空 ≤ 5% 的玻璃场景 | 失败可以多，但必须被识别 |
| 墙面对齐误差 | 相对日晷真值中位数 ≤ 3°，P90 ≤ 6° | 【估】 |
| 佐证门槛 | solar 与 map 同在、`3·sqrt(σ_i² + σ_j²)` 在 10–20° 的场景中，真实方向误差 P90 ≤ 5°；否则 15° 要收紧 | 【估】ADR-0018，2026-10-03 加入 |
| 漂移处理 | 重投影后近窗框边界的角度变化 ≤ 2° | 【估】 |
| 分割路径 | 20 帧标注天际线 IoU ≥ 0.90，失败可识别 | 【估】不达线改 CoreAI 自训模型（ADR-0010） |
| 分割 · 走廊内假天空 | 评估帧里，走廊内被判成天空的遮挡格占走廊格的比例，逐帧与合计都报；无天空的帧（天花板占满）产生的天空证据为 0 | 【估】2026-10-04 加入（评审 R02）；是诊断项，不替换上一行 |
| 太阳圆面 · 方向误差 | 被接受的确认相对日晷真值：中位数 ≤ 2°，P90 ≤ 4° | 【估】2026-10-04 测前登记（ADR-0021）；同时报拒绝、放弃、救场的次数 |
| 太阳圆面 · 误接收 | 挑战集里与太阳同高度的反光与人工亮目标：被标为有效的次数为 0（每类至少 10 次【估】） | 【估】2026-10-04 测前登记（复审 V2-01）；不为 0 则限定采集条件或加独立确认 |
| 太阳圆面 · 走动往返 | 走出再回到原点后再确认一次，两次 Δ 之差 ≤ 2°，且各自相对真值仍在上面的线内 | 【估】2026-10-04 测前登记（复审 V2-02）；只用"回到原位"不能证明偏航没漂 |

### 5a. 两个实验的做法（2026-10-04，方案 v2 §7）

**实验 1 · 分割评估。** 输入是 App 拍的帧卷片段（带重力、深度、内参）加手工描的天际线；普通照片只用于接口冒烟（`tools/segsmoke`）。Mac 上比较质量；延迟、内存、温升、掉帧在 iPhone 上量，不用 Mac 的数填。比较三条路径：Vision 迭代分割（包含点由"地平线以上 + 无近深度 + 亮且平滑"共同挑出，排除点取 LiDAR 近物）、不用 Vision 的启发式基线、手工。每张图分开记：成功、空结果、分到了错的对象、耗时——不只留成功的图。用这批样本选出的规则只叫开发结果；进独立 holdout 之前冻结算法、σ、阈值与规则版本，评估帧不再用于最终验收。第一轮（2026-10-09，84 帧，真值初稿）的做法与结果在 `spike/2026-10-09-experiment-1-segmentation.md`。

**实验 2 · 太阳圆面确认。** 记录用 `field/templates/sun-confirmation-log.csv`。挑战集至少包含：开阔天空下的真太阳；隔干净玻璃、隔脏玻璃的真太阳；云边遮住一半的太阳；**与太阳同高度的**远处玻璃幕墙反光（没有深度回波）；室内镜面或窗玻璃上的反光（有深度回波）；车漆与金属的高光；特意放到太阳高度角上的灯；屏幕。每次记：是否被标为有效、哪条检查拒绝的、买家是否确认、Δ 与日晷真值之差、是否放弃、救场分钟。统计口径：误接收率按类别分开报；方向误差只在被接受的真太阳样本上算，同时报拒绝了多少真太阳。

## 6. 三周后的决定

| 结果 | 决定 |
|---|---|
| 全部达线 | GO：进入 V1（`12-roadmap.md`） |
| 时刻与 false-valid 达线，方向或玻璃未达 | CONDITIONAL：V1 限定户外 + 晴天室内，或要求一次最小确认；继续修输入 |
| 时刻未达线或 holdout 出现 false-valid | NARROW：不做消费者产品；缩到专业采集，先修测量链 |
