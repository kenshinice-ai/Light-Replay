# 07 · 三周技术 Spike：只回答"这条测量链有没有资格进入 MVP"

版本 0.1 · 2026-09-10 · 状态：未开始

## 1. 原则

- 不做产品 UI、不做付费、不做地图、不做预览。
- 通过线在开始前预注册（本文第 5 节）；事后修订走 ADR。
- 第 3 周的 holdout 场景不参与任何调参。
- **false-valid**（质量不够却输出确定小时数）是一票否决。

## 2. 三周

| 周 | 目标 | 交付 | 场景 |
|---|---|---|---|
| **W1 · Point Core** | OneTake 采集验证器 + SunEngine | SceneRecord 导出；帧、姿态、深度、掩膜记录；镜头锚点与漂移；走廊覆盖率显示；SunEngine 单元测试通过 | 自家：开敞庭院、檐下、树冠各 1 点 |
| **W2 · Hard Cases** | 室内、玻璃、NorthResolver | 四态分割（含玻璃不确定）；深度重投影；四来源方向并行记录与融合；R2 对照仅在 RoomPlan 可用时 | 自家与已授权室内：隔玻璃 3 点、开窗 2 点 |
| **W3 · Holdout** | PP 独立真值 | 10–15 个目标点（室内外各半，含玻璃、树冠、低太阳）；固定机位延时；日晷方向真值；误差分布、失败率、时长、人工救场分钟 | 授权房源，按 `08-ground-truth-protocol.md` |

W1 的第一天先建 Xcode 工程与 `SceneRecord` 包，见 `ios/README.md`。

## 3. 指标定义

| 指标 | 定义 |
|---|---|
| 时刻误差 | 每个"阳光进入 / 离开目标"事件：`|预测 − 观测|` 分钟；只统计通过质量门槛（accepted）的场景 |
| false-valid | 未通过门槛却输出小时数的场景数；或 accepted 场景中误差 > 45 分钟且无"敏感/未知"标注的事件数 |
| 采集时长 | 从按下开始到质量门槛判定的秒数；分布与放弃率 |
| 人工救场 | 每个成功场景需要采集员之外的人介入的分钟数 |
| 玻璃可用性 | 隔玻璃场景中：失败被系统识别的比例；未识别的假天空数 |
| 方向源分布 | 每种来源相对日晷真值的误差；冲突检测的触发率与正确率 |
| 漂移 | 每场景最大漂移；重投影前后走廊内单元变化率 |

## 4. 设备与人

- 采集：带 LiDAR 的 iPhone 1–2 台；三脚架；第二台手机做延时；白卡；竖直杆（日晷）。
- 人：Lee（采集与判断）、Claude（代码与分析）、PP 采集员 1–2 人（W3）。

## 5. 候选通过线（预注册，2026-09-10）

| 指标 | 候选线 | 备注 |
|---|---|---|
| 时刻误差 | accepted 场景中位数 ≤ 10 分钟，P90 ≤ 20 分钟 | 【估】先测分布 |
| false-valid | holdout 中为 0 | 一票否决 |
| 采集时长 | ≥ 80% 的点在 40 秒内 | 同时报 P80 / P90 与放弃率 |
| 人工救场 | 中位数 0 分钟；任何场景不超过 5 分钟 | 频繁需专家校北即不成立 |
| 玻璃可用性 | 未识别的假天空 ≤ 5% 的玻璃场景 | 失败可以多，但必须被识别 |
| 墙面对齐误差 | 相对日晷真值中位数 ≤ 3°，P90 ≤ 6° | 【估】 |
| 漂移处理 | 重投影后近窗框边界的角度变化 ≤ 2° | 【估】 |

## 6. 三周后的决定

| 结果 | 决定 |
|---|---|
| 全部达线 | GO：进入 V1（`12-roadmap.md`） |
| 时刻与 false-valid 达线，方向或玻璃未达 | CONDITIONAL：V1 限定户外 + 晴天室内，或要求一次最小确认；继续修输入 |
| 时刻未达线或 holdout 出现 false-valid | NARROW：不做消费者产品；缩到专业采集，先修测量链 |
